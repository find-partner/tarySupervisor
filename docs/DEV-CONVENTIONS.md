# 开发规约（DEV-CONVENTIONS）

横向工程约定，补充各 SPEC（SRS / HLD / CONFIG-SPEC / CLI-SPEC）未覆盖的内容；
与 SPEC 冲突时以 SPEC 为准，新约定按编号追加。

## 1. 版本兼容性策略：默认不兼容

**除非规范文档明确声明某表面需要兼容，否则一律不做版本间兼容。** 允许破坏性变更，升级 = 重新生成 / 手工迁移配置，不提供迁移工具（除非 SPEC 声明）。

- 「表面」指：配置文件格式、持久化数据、IPC 契约、外部 CLI 输出等跨版本可见的接口。
- 实践含义：
  - 新增配置键不必让旧版本应用识别——旧版本遇未知键报错是既有策略（CONFIG-SPEC §1）；
  - 旧配置文件在新版本下能否解析，取决于新键是否为可选字段；是否保持这一方向的兼容由 SPEC 明确声明，未声明即视为可破坏；
  - 运行态均不落盘（内存日志环形缓冲、托盘菜单 ID、matcher hash 等），这些内部表示可随版本自由变化；
  - 需要兼容的表面必须在对应 SPEC 或本文件列出，并写明方向（向后 = 新版读旧数据；向前 = 旧版读新数据）。
- 当前已声明的兼容面（白名单，未列出即不兼容）：
  - **CONFIG-SPEC §3.5**：新版本应用解析旧配置文件——新增可选键（如 `shell`）缺省即兼容；反方向（旧版本应用读含新键的配置）不受支持。

## 2. IPC 契约约束（core/src-tauri ↔ 前端 WASM）

- **数字安全整数**：跨 IPC 的整数字段必须落在 JS `Number` 安全整数范围内（绝对值 ≤ 2^53-1）。`serde-wasm-bindgen` 对超范围的 u64/i64 反序列化直接报 `invalid type: floating point …, expected u64`。超范围的数据在**源头**截断到 53 bit 或改用字符串承载。
  - 真实事故：matcher 快捷项 hash 曾使用完整 u64（`DefaultHasher::finish()`），URL 命中后 `list_services` 整体反序列化失败、列表不可用。现于 `matcher.rs::short_hash` 截断。
- 反序列化失败会以 JS 异常抛出（`src/bridge.rs` `invoke_t`），表现为整块数据不可用且无 UI 提示——新增大整型字段前先对照本条。
- 前后端 DTO 为手工镜像（`src/dto.rs` ↔ core 序列化结构）：新增字段两侧必须同步，前端侧一律加 `#[serde(default)]`；禁用 `#[serde(flatten)]`（对嵌套对象静默降级为默认值且不报错，dto.rs 头部注释有记录）。
