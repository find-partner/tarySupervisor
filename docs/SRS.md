## 1. 引言

### 1.1 目的

本文档定义 TraySupervisor 的软件需求，包括功能需求、非功能需求、界面需求与验收标准，作为概要设计与开发实施的依据。

### 1.2 产品定位

一款跨平台（Windows / macOS / Linux）的**系统托盘后台服务管理工具**。用户将自定义命令行服务注册到本工具，通过托盘菜单查看服务列表与运行状态，并对服务进行启动、停止、重启、查看日志、在只读终端视图中观察输出、通过日志正则提取的快捷链接跳转浏览器等操作。

对标参考：Python Supervisor 的进程状态管理语义（状态机、autostart/autorestart、日志轮转），但以**桌面托盘 GUI** 形态呈现，且明确支持 Windows（Supervisor 官方不支持 Windows）。

### 1.3 范围

- **MVP（P0）**：自定义命令行服务的配置、托管、日志、正则快捷项、只读终端视图。
- **不在 MVP 范围**（列入二期）：系统原生服务管理（systemd / launchd / Windows SCM）、提权操作（UAC / sudo / pkexec）、交互式终端（可向服务 stdin 输入）、守护进程托管模型。

### 1.4 术语

| 术语 | 定义 |
|------|------|
| 服务（Service） | 由本工具以子进程方式托管的一条用户配置的命令行程序 |
| 托管（Managed） | 服务进程是本工具的直接子进程，本工具掌握其状态与输出 |
| 状态机 | 参考 Supervisor 的服务生命周期状态集合（见 FR-3） |
| Matcher | 对服务日志进行正则匹配并生成菜单快捷项的规则 |
| 只读终端视图 | 渲染服务 PTY 输出（含 ANSI 转义序列）但不可键入的查看窗口 |
| CLI（traysvctl） | supervisorctl 风格的命令行管理工具，经本地 IPC 控制常驻应用（见 FR-9） |

## 2. 总体描述

### 2.1 产品功能概览

1. 系统托盘常驻图标 + 下拉菜单（服务列表 → 二级操作菜单）。
2. 设置窗口：服务的增删改查（命令、参数、工作目录、环境变量 KV 表、日志策略、Matcher 规则）。
3. 服务生命周期管理：启动 / 停止 / 重启，状态实时展示。
4. 日志：内存环形缓冲 + 可选文件保存（按大小轮转分块）。
5. 日志正则提取 → 菜单快捷项（如"在浏览器打开 http://localhost:3000"）。
6. 只读终端视图：关闭窗口不影响服务运行。
7. `traysvctl` 命令行工具（P1）：脚本化查询与控制（status / start / stop / restart / tail / reread / update / shutdown，见 FR-9）。

### 2.2 运行环境

| 平台 | 要求 |
|------|------|
| Windows 10/11 (x64) | WebView2 Runtime（Tauri 依赖，Win11 内置） |
| macOS 12+ (Intel/Apple Silicon) | 无额外依赖 |
| Linux | X11 或 Wayland；托盘显示依赖桌面环境（GNOME 需安装 AppIndicator 扩展，Ubuntu 默认已装；KDE 原生支持）；WebKitGTK 4.1 系统库（Debian Bookworm / Ubuntu 24.04+） |

### 2.3 约束与假设

- C1：技术栈锁定为 **Tauri v2 + Rust 后端 + Rust/WASM 前端（Leptos 或 Yew，经 Trunk 构建），全程不依赖 Node.js**。
- C2：**不做托盘图标左右键行为区分配置**，三平台统一"左键（或单击）弹出主菜单"。
- C3：服务采用**单进程托管模型**：服务进程是托盘应用的子进程；默认退出应用即停止全部服务（每服务可配置 detach 行为，P1）。
- C4：终端视图默认只读；PTY 模式下可按服务配置开启**读写（交互）终端**（`term_interactive`，默认关，见 FR-6.4）；PTY 由本工具持有，关闭视图不影响服务。
- C5：MVP 不管理系统原生服务，不做提权。
- C6：环境变量替换仅支持 `${VAR}` 语法（Windows `%VAR%` 风格不支持）。
- C7：配置文件格式采用**与 supervisord 相似的 INI 风格**（`[program:<id>]` 分节、字段名与语义对齐），以复用 Supervisor 用户习惯；规范见 [CONFIG-SPEC](./CONFIG-SPEC.md)。

## 3. 功能需求

优先级定义：P0 = MVP 必须；P1 = 首个正式版应具备；P2 = 增强/二期。

### FR-1 托盘与主菜单（P0）

| 编号 | 需求 |
|------|------|
| FR-1.1 | 应用启动后常驻系统托盘，图标显示应用 logo；tooltip 显示"运行中 n / 共 m 个服务" |
| FR-1.2 | 单击托盘图标弹出主菜单（三平台一致；Windows 右键同样弹出，macOS/Linux 遵循系统惯例） |
| FR-1.3 | 主菜单结构（自上而下）：服务列表（每服务一项）→ 分隔线 → 全部启动 / 全部停止（P1）→ 设置… → 退出 |
| FR-1.4 | 每个服务是一级菜单项，其子菜单包含：① 状态行（只读，如 `● RUNNING (PID 1234)`）② 启动 / 停止 / 重启（按状态启用/禁用）③ 查看日志 ④ 终端视图（P0 只读）⑤ Matcher 快捷项（动态生成，见 FR-5）⑥ 编辑（打开设置窗口并定位到该服务，P1） |
| FR-1.5 | 服务状态在菜单中以颜色圆点 + 文本表示：STOPPED（灰）、STARTING（黄）、RUNNING（绿）、STOPPING（黄）、BACKOFF（橙）、EXITED（红）、FATAL（红） |
| FR-1.6 | 菜单为动态重建：服务增删、状态变更、Matcher 命中均触发刷新；刷新需防抖（≤300ms 内多次变更合并为一次重建） |
| FR-1.7 | 菜单项 ID 采用稳定编码（如 `svc:<id>:stop`、`match:<svc_id>:<hash>`），保证事件路由可靠 |
| FR-1.8 | 点击"退出"：若有运行中服务，弹确认对话框（列出将被停止的服务）；确认后按停止流程逐个停止再退出 |
| FR-1.9 | 应用单实例运行（二次启动唤醒/聚焦已有实例） |

**验收标准**：添加 2 个服务后，菜单层级、状态色、按钮可用性均正确；1 秒内完成状态变更到菜单刷新；连续触发 10 次状态变更仅产生 1 次菜单重建。

### FR-2 服务配置管理（P0）

| 编号 | 需求 |
|------|------|
| FR-2.1 | 设置窗口支持服务列表与编辑表单，字段：名称（唯一）、命令（可执行文件路径或 PATH 可解析名称）、参数列表、工作目录（可选，默认用户目录）、环境变量 KV 表（见 FR-2.3）、启动模式（管道捕获 / PTY 捕获，默认管道）、autostart（应用启动时自动启动，默认关）、autorestart（no / on-failure / always，默认 no）、stop_timeout_secs（默认 10 秒） |
| FR-2.2 | 日志策略配置：输出目标（仅内存 / 仅文件 / 两者），文件模式下可配置：文件路径、单文件最大字节数、分块保留份数、是否 gzip 压缩旧分块 |
| FR-2.3 | 环境变量以 KV 表格逐行添加/编辑/删除；每行有独立开关 `expand`（是否启用变量替换）：开启时值中的 `${VAR}` 按规则替换（先查本服务 env 表，再查系统环境；未定义 → 校验错误并阻止保存/启动）；关闭时值按字面量传递，不做任何解析与转义 |
| FR-2.4 | 保存时进行校验：命令非空且可解析、正则可编译（Matcher）、env 值必须 UTF-8、替换开启时 `${VAR}` 引用可解析、无循环引用；校验错误逐项展示并阻止保存 |
| FR-2.5 | 保存后服务立即出现在托盘菜单中；删除服务时若在运行则先停止（需确认） |
| FR-2.6 | 配置持久化为单文件，格式采用**与 supervisord 相似的 INI 风格**（`[program:<id>]` 分节，C7），路径：`~/.traysupervisor/config.ini`（Windows 为 `%USERPROFILE%\.traysupervisor\config.ini`）；完整格式规范见 [配置文件规范（CONFIG-SPEC）](./CONFIG-SPEC.md)。支持手动编辑后热加载（检测文件变更并 diff 应用，不重启未受影响的服务；校验失败时沿用上一次有效配置并提示） |

**验收标准**：KV 表逐行添加 3 个环境变量（其中 1 行开启替换引用另一行）后保存并启动服务，子进程环境正确；`${UNDEFINED_VAR}` 在保存时被拦截；点击列表中任一服务后，编辑表单完整回显该服务的全部字段（ID、显示名、命令行、工作目录、启动捕获模式、autostart/autorestart、startsecs/startretries/stopwaitsecs、日志策略、环境变量表、Matcher 表）。

### FR-3 服务生命周期管理（P0）

| 编号 | 需求 |
|------|------|
| FR-3.1 | 状态机：`STOPPED → STARTING → RUNNING → STOPPING → STOPPED`；异常退出进入 `EXITED`；按 autorestart 策略可进入 `BACKOFF`（指数退避重试，最多 5 次）或 `FATAL` |
| FR-3.2 | 启动：以直接子进程方式 spawn（Unix：`setsid` 新会话；Windows：`CREATE_SUSPENDED` + 绑定 Job Object），注入环境变量（系统环境 + 服务 env 表） |
| FR-3.3 | 停止：优先优雅停止——Unix 向进程组发 `SIGTERM`；Windows 优先尝试 `GenerateConsoleCtrlEvent(CTRL_BREAK_EVENT)`（仅管道模式下的直接子进程），超时（stop_timeout_secs）后强杀整树——Unix `SIGKILL` 进程组，Windows `TerminateJobObject` |
| FR-3.4 | 重启 = 停止（优雅+强杀）→ 等待进程完全退出 → 启动 |
| FR-3.5 | 退出码、停止原因（正常/超时强杀/信号）记录到日志与服务记录中 |
| FR-3.6 | 严禁经 shell 包装启动（`cmd /c`、`sh -c`），避免孙进程不可控；用户输入的参数按数组直接传给目标程序 |
| FR-3.7 | 应用退出时对全部运行中服务执行 FR-3.3 停止流程；若服务配置了 detach（P1），则脱离 Job Object / 新会话后保留运行 |

**验收标准**：Windows 下启动 `python -m http.server` 后停止，无残留 python 进程（含其子进程）；Unix 下 kill 服务进程组后 10 秒内状态回到 STOPPED；autorestart=always 时 kill -9 后自动拉起。

### FR-4 日志查看与存储（P0）

| 编号 | 需求 |
|------|------|
| FR-4.1 | 捕获 stdout 与 stderr（管道模式：独立 pipe；PTY 模式：单一输出流），带时间戳合并存储；允许按流分色显示 |
| FR-4.2 | 内存环形缓冲：每服务默认保留最近 2000 行（可配），超出即丢弃最旧行 |
| FR-4.3 | 文件保存（可选）：写入即落盘；达到 `max_file_bytes` 轮转，旧文件按 `.1 .2 …` 计数后缀分块，保留 `max_files` 份，可选 gzip 压缩 |
| FR-4.4 | 日志查看窗口：自动滚动到底部（用户上滚时暂停，回到底部恢复）；支持复制；显示服务状态与 PID |
| FR-4.5 | 日志按 UTF-8 解码，非法字节以替换符显示（GBK 等编码支持列为 P2 可配置项） |
| FR-4.6 | 日志窗口关闭不影响捕获（捕获在后端持续进行，只要服务在运行） |

**验收标准**：以 10MB/文件、保留 3 份配置，灌入 50MB 输出后目录中存在 3 个分块文件且总占用 ≤ 预期；日志窗口滚动流畅无卡顿。

### FR-2A 设置页交互（P0）

| 编号 | 需求 |
|------|------|
| FR-2.7 | **空态引导**：设置页打开后未选中任何服务、也未点击"新建"时，编辑区不显示任何表单，显示引导信息：一句话产品简介（注册命令行服务 → 托盘启动/停止 → 日志与终端观察 → 正则提取快捷链接）与"点击左侧 + 新建服务 开始配置"的提示 |
| FR-2.8 | **标签页分组**：编辑/新建表单按 **基本设置 / 环境变量 / 日志 / 快捷项（Matcher）** 分四个标签页；每个标签页有独立的"保存本页"按钮，保存即提交该页变更（实现上以整份配置快照合并提交，校验规则 FR-2.4 不变）；有未保存变更的标签页显示"未保存"标记；切换标签页不做隐式保存 |
| FR-2.9 | **新建向导**：新建服务走 step-by-step 向导：① 基本设置（ID/显示名/命令行/工作目录/捕获模式/交互终端/autostart/autorestart 等）→ ② 环境变量 → ③ 日志 → ④ 快捷项；每步可"上一步 / 下一步 / 跳过"；基本设置中 ID 与命令行非空方可进入下一步；最后一步"保存并完成" |
| FR-2.10 | **保存生效提示**：保存**不自动重启**运行中的服务；若被保存的服务正处于 RUNNING/STARTING，保存成功后提示"配置已保存——服务正在运行，需重启后新配置才会生效"，并提供"立即重启"按钮（调用 FR-3.4 重启流程）；新建/已停止的服务保存后无需提示 |

**验收标准**：首次打开设置页仅见空态引导；点击已有服务后表单分四个标签页完整回显；修改"环境变量"页并点该页"保存本页"后，其余页字段保持原值；对 RUNNING 服务保存后出现重启提示，点"立即重启"后服务重启且新配置生效。

### FR-5 日志正则匹配与快捷菜单项（P0）

| 编号 | 需求 |
|------|------|
| FR-5.1 | 每服务可配置多条 Matcher：`pattern`（Rust regex 语法）、`template`（菜单文案，`{0} {1}` 引用捕获组）、`max_items`（默认 5） |
| FR-5.2 | 对新到达的日志行流式匹配；命中后按模板生成菜单快捷项（去重：同一匹配值只保留一项，以匹配结果哈希为键） |
| FR-5.3 | 内置模板："HTTP URL"（`https?://[^\s]+`）命中后菜单显示"🌐 打开 {url}"，点击调用系统默认浏览器 |
| FR-5.4 | 每服务快捷项总数 ≤ `max_items`（上限 10），新命中按 LRU 淘汰 |
| FR-5.5 | 正则在保存时编译校验；服务重启后清空该服务的 Matcher 菜单项（旧输出不再展示） |
| FR-5.6 | 打开链接前对 URL 做基本校验（仅 http/https），防注入其他 scheme |

**验收标准**：服务打印 `Serving at http://127.0.0.1:8000` 后 1 秒内菜单出现"🌐 打开 http://127.0.0.1:8000"，点击打开浏览器。

### FR-6 只读终端视图（P0）

| 编号 | 需求 |
|------|------|
| FR-6.1 | PTY 模式下，提供窗口内只读终端视图：解析 ANSI/VT 转义序列并渲染（颜色、光标位置、清屏等基本序列） |
| FR-6.2 | **关闭终端视图窗口不影响服务运行**（PTY master 由后端持有，视图仅为输出订阅者） |
| FR-6.3 | 管道模式下"终端视图"入口显示为纯文本日志流（无 ANSI 渲染需求，退化为 FR-4 视图） |
| FR-6.4 | **交互（读写）终端**（PTY 模式）：每服务可配置 `term_interactive`（默认关，需 PTY 模式）；开启后终端窗口接受键盘输入并按字节转发至服务 stdin——可打印字符按 UTF-8 编码，Enter=`\r`、退格=`DEL(0x7f)`、Tab、Esc，Ctrl+字母（如 Ctrl-C=`0x03`、Ctrl-D=`0x04`）与方向键按 ANSI 转义序列（`ESC [ A~D` 等）转发；行编辑由子进程终端行规程处理，本工具不做本地行缓冲 |
| FR-6.5 | 交互终端窗口底部提供"只读 / 可写"运行时开关（默认取配置值），开关状态仅作用于当前窗口；支持粘贴：粘贴文本按输入转发至服务 stdin |

**验收标准**：PTY 模式下运行输出彩色进度条的服务（如 `pip download`），视图正确渲染颜色与进度行刷新；关闭视图再打开，历史输出仍在；`term_interactive=true` 的服务运行 `python -i` 或 `cat` 时，键入内容可见回显（cat 场景）、Ctrl-C 可中断前台命令、方向键可翻历史（python REPL 场景）；粘贴多行文本按行进入 stdin；未开启 `term_interactive` 的服务终端视图仍为只读。

### FR-8 开机自启（P2）

注册表（Windows）/ launchd Agent（macOS）/ XDG autostart（Linux），设置窗口内开关。

### FR-9 命令行工具 traysvctl（P1）

supervisorctl 风格的命令行管理工具，完整规格见 [命令行工具规格（CLI-SPEC）](./CLI-SPEC.md)。

| 编号 | 需求 |
|------|------|
| FR-9.1 | 提供 `traysvctl`，子命令至少覆盖：`status`、`start`、`stop`、`restart`（均支持 `all`）、`tail [-f]`、`reread`、`update`、`shutdown`、`version`、`validate` |
| FR-9.2 | CLI 经本地 IPC（Unix domain socket / Windows named pipe，仅当前用户可访问）与常驻托盘应用通信，复用 HLD §4 Command 语义；不引入守护进程（C3 不变，CLI 仅是常驻应用的客户端） |
| FR-9.3 | 常驻应用未运行时，各子命令的行为与退出码按 CLI-SPEC §5/§6 定义 |
| FR-9.4 | `status` 输出的状态集合与 FR-1.5 一致并含 PID；`validate` 离线校验配置文件并逐项报告错误（与 FR-2.4 同一校验规则） |

**验收标准**：应用运行 2 个服务时，`traysvctl status` 正确显示状态与 PID；`traysvctl stop all` 后托盘菜单与 `status` 均显示 STOPPED；关闭应用后 `traysvctl status` 退出码为 3。

## 5. 界面需求

1. **托盘菜单**：见 FR-1（唯一常驻交互入口）。
2. **设置窗口**：左侧服务列表 + 右侧编辑区；编辑区三种状态——空态引导（FR-2.7）、编辑模式（按 基本设置/环境变量/日志/快捷项 标签页分组，FR-2.8）、新建向导（FR-2.9）；环境变量为 KV 表格（Key / Value / 替换开关 / 删除按钮，底部"添加一行"）；Matcher 为类似表格（Pattern / 模板 / 上限）。
3. **日志窗口**：每服务一个，等宽字体，工具栏（暂停滚动 / 清空视图 / 复制全部 / 打开日志目录）。
4. **终端视图窗口**：每服务一个（PTY 模式），黑底等宽；默认只读，`term_interactive` 服务提供"只读/可写"开关与键盘输入（FR-6.4/6.5）。
